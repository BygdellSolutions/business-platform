# Lessons

Rules learned from corrections by the project owner. Review at session start; add an entry after every correction.

- **"Organization" always means the tenant.** A customer that is a business is a `company` (customer type `person` | `company`).
- **Module fields are normal domain attributes; UDFs extend, they do not replace.** Stable attributes of a domain entity (a horse's `birth_year`, `sex`, `breed`) are real, validated columns in that module, not UDFs. UDFs add organization-specific fields on top of the normal model.
- **A transaction's lifecycle status is not its invoicing state.** `draft` / `completed` / `cancelled` describe the transaction only; `completed` means finalized and ready for future invoicing, not "uninvoiced". Invoice state will be its own relationship, not another lifecycle status.
- **Totals and VAT breakdowns sum the stored line amounts.** Never recompute grouped VAT from grouped net totals; per-line half-up rounding is the single rounding rule.
- **Keep the header minimal.** The Transaction header has no note or other free text until a real need appears.
- **Boundary tests enforce imports and registrations, not vocabulary.** Generic code and docs may use ordinary domain words. What must hold is who imports whom: core, generic capabilities and modules meet only through the core registry.
- **Required custom fields participate in finalizing a record, without Sales importing Custom Fields.** Core exposes a generic lifecycle-validation seam: capabilities register validators and modules call the seam. Failures carry the record type, id, field and label so a client can locate the problem.
- **`show_on_invoice` means "eligible to be snapshotted".** Invoices store the rendered label and value at issuance and never resolve live custom-field or reference data for an existing invoice.
- **Role checks live in core, not in feature modules.** Use `require_role` / `roles_required`; the role is always the one in the active membership.
- **Automated tests never touch the development database.** pytest and Playwright use a separate PostgreSQL server (`postgres-test`) via `TEST_DATABASE_URL`, rebuilt from migrations. A guard refuses anything not named `*_test` or hosted on the development server, and there is no fallback to the development database.
- **Enforce the money rule where money lives, not as a global ban.** Decimals are strings via branded types, scoped lint rules in the money-handling folders and tests; `parseFloat`, `Number` and `Math` stay available elsewhere.
- **The frontend never copies backend limits.** Digit counts, ranges (0 to 100, greater than zero), precision and uniqueness are the backend's rules. The frontend checks only that a typed value has the right shape and shows the backend's 422 on the field; a copied limit would drift from the backend.
- **A mutation must also refresh the router, or Back shows stale lists.** Next.js reuses cached pages on browser Back/Forward. After a create, `router.push()` is followed by `router.refresh()`; after an edit or a status change, `router.refresh()`. This was found by a browser test (Back to a list visited before a create did not show the new record), so keep that test.
- **End-to-end specs share one database, so a spec never depends on what other specs created.** Look records up by a unique name; never rely on "the first N rows" (the dashboard preview) or on a name being absent from a capped list. Fixtures that must appear in a capped list get a leading `000` so they sort first.
- **A picker selects by id, never by text, and an unchanged reference is never re-sent.** Two customers can have the same name, and a customer can become inactive after being assigned. The picker holds `{id, label}`, displays the current selection even if it is no longer offered, and submits only the id; an edit sends a relationship only when the user changed it, which matches the backend (it checks only new targets).
- **A keyboard test needs a real form.** In jsdom, Enter does not submit a form that has no submit button, so a test of "Enter must not submit" passed even with the guard removed. Give such test forms a submit button, and confirm with fault injection that the test fails without the guard.
- **Stale edits are refused by the server, not detected by the screen.** A tab cannot know it is stale. Anything a person edits in a browser carries the version it is based on, and the server compares it under its row lock before changing anything. Use a counter, not `updated_at` (ties; a parent does not change when a child does), and give the token the granularity of what is edited (header vs lines vs the whole document).
- **A conflict must never destroy what the user typed.** After a stale refusal keep the draft, switch Save off, show what is on the server now, and let the user choose; loading the latest around an open editor is fine because it does not touch the editor's own state. Throwing the draft away is the user's choice, not the default.
- **A mutation test that has no effect on the page proves nothing.** Mocking `router.refresh` as an instant call hides the pending state of the real router (it suspends until the new page arrives). The test harness models that with a gate, and the UI dims what is about to change.
- **A single-flight guard needs a same-instant test.** Disabled buttons cover the user who clicks twice; only a test that fires two clicks inside one act proves the guard itself.
- **Equivalent mutants are reported, not hidden.** When a fault cannot be observed because another guard makes it unreachable (judging a save by the newest version when Save is already off for a newer one), say so instead of counting it as covered.
- **Genericity is enforced by a test, not by intention.** A generic layer gets a boundary test: imports limited to generic layers, no comparison of metadata to literals, no domain words in code or comments (and the check is tested against bad samples). Without it, the first "just for this field" special case arrives quietly.
- **Read what the backend enforces on write before designing the form.** The Custom Fields API checks every required field and every dependency against the FINAL state of a record on each write, so the UI saves a record's fields together (only the changed ones) and sends a parent change and its cleared children in one request. Field-by-field autosave would have been refused.
- **Answers belong to the question that was asked, including the function that asked it.** A picker whose choices depend on another field must treat a changed search function as a new question; otherwise the old parent's choices stay visible until the new answer arrives.
- **Closing or clearing a control must not pop something over the next control.** Returning focus to a picker after "Clear" re-opened its list on top of the Save button; found only because a browser test clicked Save. Restore focus without triggering open behavior.
- **Keep the label text clean.** A visible `*` inside a `<label>` changes the label's text for tests and for tools that match it; draw the marker with CSS and express the meaning with `aria-required`.
- **Organization context belongs in the URL.** A shared cookie would let one tab silently re-target another tab's writes; the BFF takes the organization from the URL and FastAPI verifies membership.
- **Compare `Origin` with the `Host` header, and redirect with a relative `Location`.** Next may normalize the request URL host (for example `localhost` for `127.0.0.1`), which would reject legitimate same-origin requests or move the browser to a host without its cookie.
- **Never assume data the platform does not know.** A currency (or any financial attribute) is configured explicitly; a migration must not backfill an assumed value into existing records, even a likely one. Keep the column nullable, show "not recorded", and offer an explicit, confirmed action for the owner to state it. Prove it with a migration test on data that has no value.
- **Do not promise guarantees you do not control.** The invoice counter rolls back with the issuing transaction and issued numbers are never reused, but that is not "gapless numbering" as a business guarantee: whether a jurisdiction requires it is policy, so neither the docs nor the schema claim it. Say what the mechanism does, not what a regulation might want.
- **Database triggers protect a module's own tables; cross-module rules live in the core seam.** An immutability trigger on invoice tables is fine. A trigger that makes the Sales lifecycle depend on Invoicing tables is not: Sales would silently depend on another module. The veto goes through the lifecycle seam as a registered validator, protected by locking tests.
- **Do not model speculative features.** No one-value enum (`document_type = 'invoice'`) for credit notes that are not designed, and no uniqueness constraint (`number_text`) that is really formatting policy. Add the column or constraint with the feature that needs it.
- **A change that must not race a creation takes the same row.** The currency check and the creation of prices serialize on the organization row (`FOR SHARE` for creators, `FOR UPDATE` for the change); otherwise "refuse once prices exist" has a window. Prove each ordering with real, separate connections and a request that is still waiting while the other side is uncommitted.
- **A composite foreign key with a nullable column is not enforced for NULLs (MATCH SIMPLE).** `(organization_id, id, billing_customer_id, currency)` only protects a row whose own `currency` is NOT NULL. Make the referencing column NOT NULL, or the "same currency" rule silently does not apply.
- **When a test must undo a database rule, do it inside the rolled-back test transaction.** PostgreSQL DDL is transactional: `ALTER TABLE … DISABLE TRIGGER` inside the test's transaction recreates a pre-feature row and disappears with the rollback.
- **A lock does not refresh what the session already remembers.** `SELECT ... FOR UPDATE` through the ORM returns the object the session already holds without reloading its attributes, so "verify under the lock" silently verified stale data. A tamper test (change a source by raw SQL, then issue) found it. Reads whose point is to see the locked rows now bypass the identity map (`populate_existing`).
- **A control test is what makes a negative test mean something.** "No live table is queried" passed vacuously when a backspace character replaced `` in the regex while I moved it; only the control (a Sales read MUST be seen touching live tables) failed. Pair every "nothing happened" assertion with one that shows the observer can see something.
- **A natural race needs a gated twin.** Simultaneous requests prove the outcome is always one of the consistent ones, but they may never hit the interleaving that matters. Pause one side while it holds its locks (a session, or a request stopped at a gate), show the other side still waiting, then release; do this for each ordering. Where the interleaving cannot be forced (lock ORDER, the planner's row order is stable), assert the statement itself (`ORDER BY id ... FOR UPDATE`).
- **Layered defenses produce equivalent mutants; prove it, do not assume it.** The ordinary "already invoiced" check and the unique key give the same answer, and an item insert is already serialized by its foreign key's lock. Remove one layer at a time at the level where it is the only guard (the migration, a probe in Postgres) to show each layer is real, and report the ones that are redundant by design.
- **A test that passes by luck is a flaky test.** Two transactions with the same date and (inside one rollback-only database transaction) the same `created_at` came out in id order, which is random. Give test data distinct values wherever order is asserted, and run a file several times after writing it.
- **Triggers on a parent and its children must agree on cascades and on the order of a state change.** Deleting a draft cascades to rows whose trigger looks up the (already deleted) parent; issuing must change the children (snapshots) while the parent is still a draft, then flip the parent. Test the cascade and the flip, not only the refusals.
- **Mutation lists rot silently.** A fault whose anchor text no longer matches reports "setup error", and an edit that never persisted looks like success. Treat setup errors as failures, and check that each fault actually changed something before counting it as detected or survived.
- **An unknown outcome is checked, never retried and never assumed.** A network failure or a 5xx while issuing says nothing about whether the invoice was issued. The screen re-reads the invoice (`verify`), offers no new attempt until that check has answered, and then shows what the server has; a retry would be refused anyway (stale or already issued), but the user must not be told "failed" about something that committed. Test it by letting the backend finish and dropping only the answer (`route.fetch()` then `route.abort()`).
- **Show a stored document from itself, and prove it by making the live world disagree.** The tests that matter are the ones where the live customer, item and fields say something else than the snapshot, plus a static boundary (no live imports, no requests for live records) and, in the backend, an SQL recorder. A test whose live data happens to equal the snapshot proves nothing.
- **A "no arithmetic" rule needs inconsistent data and a static check.** Feed figures that do not add up and assert each is shown exactly; a regex scan of the code is a second net, but it must ignore string literals (a test id such as `line-quantity` looked like subtraction).
- **Do not offer a control, or an explanation of one, to someone who cannot use it.** A reader looking at an issued invoice was told "only owners can issue or delete a draft". Gate by state first, then by role; and give a reader no form at all, not a form that ends in a 403.
- **Redundant guards are equivalent mutants until the flag behind them goes.** Late answers after navigation were guarded in the handler and again inside `refresh()` and by React ignoring updates on an unmounted component, so removing any one guard survived. Remove the shared cause (the "left the screen" flag) to show the layers are real.
- **Error text inside a `<label>` changes the label (again).** Use the shared `FieldShell`, whose error sits outside the label, instead of writing a new label-with-error structure.
- **A test harness that keeps `initial` in `useState` ignores a changed `initial`.** To simulate switching organization, remount it with a `key`, as the real navigation does.
- **Escapes in generated code are easy to corrupt.** A script that wrote a regex containing `\b` or `\n` produced a backspace and a real newline; the tests even kept passing for a while. After generating code from a script, run the type checker and look at the bytes of anything with escapes.
- **A library's text mode can quietly break your formatting.** ReportLab's CJK wrap mode splits on every kind of space, including the no-break space used to group digits, so a grouped amount broke between its groups in a narrow column. Use the plain wrap mode for figures, size figure columns from the widest printed value, and keep a test with an amount that is too wide for a default column.
- **Redundant-by-design layers show up as surviving mutants: say so, or add the test that separates them.** Removing the organization filter from the PDF's invoice lookup survived because the read that follows is scoped again; the leak it would cause (a foreign DRAFT answering 409 instead of 404) was untested. For every guard ask what the observable difference is, and test that difference with data built for it (a foreign draft, not only a foreign issued invoice).
- **Races need distinguishable outcomes.** A deterministic renderer makes two racing renderings identical, so "both callers got the winner's bytes" is true even if each returned its own. Wrap the renderer so every call is unique and use gates, then assert the response equals the stored row and not the caller's own rendering.
- **Joining text across page breaks needs the page furniture removed first.** A running footer, a repeated table header and the figure cells of a split row all sit inside a long text on the extracted page text; strip them precisely (a bounded pattern, not `\S*`, which swallowed the whole document) before asserting that nothing was truncated.
- **CHECK constraints defeat tampering tests.** To show that a PDF prints stored figures that disagree with each other, the table CHECKs that tie them together have to be dropped inside the rolled-back transaction (DDL is transactional in PostgreSQL), not just the triggers switched off.
- **Prove the font set is the one that was reviewed.** Verify the pinned checksums when the fonts are loaded, not only in a test that calls the verifier directly; a test must reset the process-wide cache to show that loading itself refuses a changed file.
- **Check the PDF for what it uses, not for what it names.** ReportLab lists its default font (Helvetica) in every page's resources without drawing anything with it. Assert on the fonts that reach a text-showing operator, and that each of them is embedded.
- **"Has no buttons" is the wrong way to say "cannot change anything".** Four component tests and two end-to-end specs asserted that an issued invoice had no button at all; adding Download PDF broke them. Assert the absence of the mutation controls by name, and the exact set of what is left (`download-pdf` only), so a later read-only control does not need six edits.
- **A fixed layout is a promise about data you may not have.** Fixed figure columns were fine for the sample invoice and wrapped, then overflowed, with the widest values the database allows (18-digit totals, 12-digit line amounts). Derive limits from the column definitions, build a worst-case document from them, and test positions (on the page, no overlap), not only extracted text, which reads the same off the page.
- **`Session.rollback()` inside a service kills a rollback-only test.** A shared test session sits on an outer transaction; a bare `rollback()` in code under test rolls the whole test back (and `commit()` silently does nothing). Use a savepoint (`begin_nested()`) wherever a request must undo only its own part, as in setup-link redemption.
- **An autouse fixture does not run after the fixture a module requests with `usefixtures`.** The throttling tests set a setting in an autouse fixture that `session_mode` then reset, so every request shared one source. Make the dependency explicit (`def fixture(session_mode, monkeypatch)`).
- **Do not defend a throttle with state an attacker can write.** A per-account `throttled_until` that failed logins extend lets anyone who knows an email deny that account for as long as they like. Count failures in a sliding window, never record refused attempts, and exempt sources that have already logged in successfully, so a block ends when the failures age out and the owner on their usual source is never affected.
- **Bound the queue in front of the expensive thing, not only the thing.** A semaphore around Argon2 limits CPU but lets requests wait (and threads and memory pile up) without limit. Admission counts running plus waiting and refuses beyond that at once with 503.
- **Make the clock a seam.** Authentication code that calls `datetime.now()` directly cannot be tested for idle and absolute expiry without sleeping; one `clock.utcnow()` attribute that tests replace lets every lifetime be proved at its exact boundary.
- **Two guards that make each other redundant need a joint fault to be proved.** The inactive-user check exists in session lookup and again in `get_current_user`; removing either alone survives. Remove both together and the test must fail.
- **A link opened in the tab you are already on is a fragment change, not a page load.** A secret read once from `location.hash` at mount misses the second link; listen for `hashchange`, take the new fragment and remove it again.
- **After a click that starts a login, wait for the login to finish before the next `goto`.** A test that clicked "Sign in" and went straight on aborted the in-flight login navigation and landed on the login page; wait for the URL to leave `/login`.
- **A mocked `Response` can be read only once.** `mockReturnValue(response)` hands the same object to every call, and the second `await response.text()` throws. Use `mockImplementation(() => makeResponse())`.
- **Validate the text as written AND after the URL parser, and build the answer from the parsed parts.** `new URL()` quietly normalizes dot segments and escapes odd characters, so a destination that looks bad can become acceptable; and a destination built from `pathname + search` can never be an external URL, which makes the earlier prefix and origin checks redundant. Say so, and prove the layers with a joint fault that also makes the function return its input.
- **A header that the framework adds in memory is not a header the server sends.** `NextResponse` showed `x-middleware-set-cookie` in a unit test (it would have exposed the session token to scripts if it were real); only a real request shows what leaves the server, so a Playwright spec checks the live response headers.
- **A cookie that is `HttpOnly` cannot be echoed by script, so the pre-login secret travels twice by design:** an HttpOnly cookie, and the same value in the response body that the page puts in a header. Another site can do neither.
- **Run the existing suites under the new mechanism instead of rewriting them.** One `signIn` helper that branches on the run's mode let the tenant-isolation, customers, catalog, horses, transactions and invoices specs run unchanged under real authentication; the few that need the old mechanism (forged dev headers) are excluded by name with the reason written down.
- **Inside a rollback-only test `now()` is the transaction start, so "did this row change?" proofs on timestamps are blind.** A fault that touched an organization's `updated_at` survived because the row was created in the same transaction; set the timestamp to a fixed past value first, or prove it end to end where transactions differ.
- **A mutation that only breaks the happy path is not detection of the bug it names.** Committing the organization early failed every test because the savepoint exit then errored, not because atomicity was checked; restructure the mutant so it commits early and still returns normally, then see which test notices.
- **A guard that forbids a word in a layer is a design decision, not a nuisance: when a legitimate case appears, mark the one exception in the source and let the test honour exactly that marker.** Writing the event row in the organization service (instead of teaching `security_events.record` about organizations) kept authentication code tenant-free; the single reference column carries an explicit marker.
- **Core must not import schemas: pass plain validated values down and let the API layer own the schema.** The service takes a dict and fingerprints it; it never sees the request model.
- **Never run `alembic` (even a read-only `check`) without setting the database URL in the same command.** The shell forgot `DATABASE_URL` once and the command silently targeted the default (development) database; it was harmless only because `check` does not write.
- **A user-row lock does two jobs at once: a fresh permission read and serialization.** Take it before judging the capability, re-read with `populate_existing`, and have the operator's change take the same lock; then a revoke either waits for a creation in flight or refuses the next one, with no other coordination.
- **When every operation takes the same lock in the same order, deadlock freedom is by construction, not by luck.** Lock the whole membership set of one organization in a single `ORDER BY id FOR UPDATE` statement; do not lock "actor, then target, then owners" in separate steps.
- **`SET CONSTRAINTS ... IMMEDIATE` sticks for the rest of the transaction.** A test that fires deferred triggers to see them refuse must switch back to `DEFERRED` afterwards, or the next statement is checked immediately and a legitimate swap fails.
- **A deferred owner-count trigger is not enough on its own.** Two transactions that each remove a DIFFERENT owner each see the other owner and both commit (write skew). Serialize the check (a per-organization advisory lock taken in the trigger) and still keep the application lock first.
- **A defence that always produces the same outward answer hides a missing application check.** The trigger plus a commit-time mapping to `last_owner` made removing the application check invisible; only a JOINT fault (application check and trigger both removed) proves each layer.
- **Gate a request between authentication and the lock to prove authority is re-read.** The gate pauses the first call of the locking function while the other side commits; the released request must act on what is now true.
- **A pure-presentation helper deserves the same independent matrix test as the backend rule it mirrors, but is never the authority.** `offered()` hides buttons; a stale screen is answered by a refusal that is displayed, and the list is re-read after any answer.
- **Do not let a helper that builds test users reuse one login per role.** A second `addMember("admin")` collided on the email; derive a unique login for repeats.
- **A bearer secret that must survive a sign-in belongs in memory, not in a redirect.** The invite page signs the person in and accepts on the SAME page with the same in-memory token; any design that sends the user through `/login?next=...` has to put the secret in a URL, a cookie or storage.
- **Under READ COMMITTED a locked set is a snapshot of when the statement began.** A row inserted by a transaction that commits while you wait for its locks is not in your result: answer "does this exist now?" with a fresh statement after the locks (the same-person retry of an acceptance was a 404 until it did).
- **Never end a test with `monkeypatch.undo()` when fixtures patched settings.** It also undoes the authentication mode; restore only the function you replaced.
- **A unique index is the last defence, not the first.** The explicit "already pending" and "account exists" checks give the right answers under the locks; the partial unique index and the unique email catch what slips through, and a joint fault proves both are needed.
- **A partial unique index cannot use `now()`.** Model expiry as a state a later write makes explicit (revoke the expired row before replacing it), and say so.
- **Raw SQL in a test bypasses the ORM identity map.** After `UPDATE`ing a row the test's session still holds the old object; reload before asserting what the code under test reads.
- **A build that works because the build machine happens to have the right environment is a deployment bug.** `/setup` was prerendered with whatever `AUTH_MODE` the build had; a clean image build would have baked a 404. Build the image under several irrelevant environments and compare behaviour, and guard the manifest of prerendered routes.
- **A framework's "fail at startup" may only log.** A standalone Next server logs a throwing `register()` and serves 500s forever. Test the PROCESS (exit status, container state), not the function that throws, and make production call `process.exit(1)`.
- **Test an isolation claim with both an inspection and a control.** The topology test reads `PortBindings` (the authority) and a control that the frontend binding IS found; a `docker port` that prints nothing proves nothing on its own.
- **A grep over an image needs a positive control.** The scan for a backend URL in the browser bundle first proves it finds a string the bundle really contains.
- **A health check that only connects calls a failing server healthy.** The TCP check was explicitly interim (D1); D2 made the backend's check READINESS and the frontend's LIVENESS.
- **Readiness is not liveness, and a restart policy must only ever see liveness.** A database outage must make the backend unready, never dead; test it with a PAUSED database (a hung connection is worse than a refused one), and keep liveness `async` so a pool of threads stuck on the database cannot make a live process look dead. A probe that waits needs a timeout AND single-flight, or the probes themselves pile up.
- **Pydantic prints `input_value` for the WHOLE input when validation fails** (database URLs with passwords, every secret). Set `hide_input_in_errors`; the same goes for SQLAlchemy's `ArgumentError` on a malformed URL (it quotes the string). Test the failure output with sentinel secrets.
- **`logging.config.fileConfig` disables every existing logger by default** (Alembic's `env.py` does it); a migration run inside a process that configured its own loggers silenced them. Pass `disable_existing_loggers=False`.
- **Importing a module package imports its `__init__`.** The migration job could not import the models without the web settings because each module's `__init__` imports its API. The migrations never read the models, so the job passes its connection and loads no metadata.
- **A session-level advisory lock must live on the connection that does the work.** Run Alembic on the SAME connection that holds the lock, and prove the lock with two real processes (and with a mutation that removes it).
- **`GRANT` by a non-owner only WARNS.** A test that expects "permission denied" for `GRANT ALL ... TO PUBLIC` needs to check the resulting ACL instead. `CREATE DATABASE` refuses a transaction block, so a denial probe needs autocommit.
- **Default privileges belong to the role that creates objects.** `ALTER DEFAULT PRIVILEGES FOR ROLE owner` covers the owner's FUTURE objects; a migration job that reconciles grants after every upgrade covers databases whose defaults were never set. Test each alone.
- **A role-restricted test run needs a list of the tests that ARRANGE state with owner rights** (`alter table ... disable trigger`): they test the arrangement, not the application. Deselect them by name and say why.
- **`docker compose up <one-shot>` in the foreground never returns while its dependency keeps running.** Start the dependency with `up -d --wait` and run the one-shot with `run --rm --no-deps`.
- **A suite that passes on your machine may be quietly using your `.env`.** Reproduce each CI job from a clean checkout (no `.env`, a fresh disposable database, the CI Python): nine tests relied on a developer's `AUTH_MODE=dev` and a known dev database URL. Tests must set what they need (or skip with a reason) and never read a developer file by accident.
- **YAML 1.1 reads the key `on` as the boolean `true`.** A parser-based workflow test must look up both.
- **Make the CI refuse its own wrong defaults.** `E2E_BROWSER` falling back to Edge is right on a laptop and silently wrong on a runner; in CI it must throw. The same goes for a database URL: assert the one thing that is allowed rather than the things that are not.
- **A guard that proves a permission must prove WHO ran it.** The role suite now refuses to start unless its connection is a restricted role, and a test hands it the owner and the superuser.
- **A static test beats a reviewer's memory:** "every API route is instrumented", "only `lib/backend.ts` fetches", "trust headers are named in one place" are one regex each.
- **A backup is not verified until it has been restored somewhere isolated and the restored state has been checked.** A file with a size and a hash is a candidate. The drill restores into a separate server with different role names and compares content fingerprints, because "the restore finished" and "the restore is the data" are different claims.
- **Redundant guards need a joint fault to be tested.** The restore tool refuses an existing output twice (an early check and an atomic no-overwrite publish); removing either alone changes nothing observable, so only removing both proves the protection. Report single faults that survive for that reason instead of hiding them.
- **A verifier's own lists must be tied to the schema by a test.** The list of required triggers and functions is compared with a freshly migrated database, so a new guarantee cannot be added without teaching the verifier. And check what the database already enforces before claiming a verifier check is the only barrier: the PDF CHECK constraints refuse a bad row, so the verifier tests drop them first.
- **Scrub the whole URL, not just its credentials.** A client that quotes `postgresql://user:pw@host/db` leaks the host and database name too; a scrubber that keeps them found only because the test asserted the host was absent.
- **A guard that exists to stop the drill from becoming a merge gate is also a test.** A static test asserts the restore drill is not in `deploy/tests` (the merge-gating container job) and not in `ci-gate`.
- **A route inventory needs a control that it sees routes.** FastAPI 0.142 keeps each included router as one wrapper route (`original_router`), so a walk over `app.routes` looking for `APIRoute` found nothing and "every write is guarded" passed on an empty list; only the control ("the inventory contains POST /api/customers") failed. Walk into included routers, and keep the control.
- **A server component must not import a module that imports React hooks, even for a constant.** `lib/profile.ts` (labels) imports `lib/forms.ts` (hooks), so a server-rendered details view that only wanted the labels broke the dev server and the build; `tsc` and lint were green. Run the build (or a Playwright spec) after adding a server component.
- **A limit on an entitlement must close every path to it, not only the one being discussed.** I recommended letting a transfer exceed the owned-organization limit; the owner refused, because transfer would then be a loophole. The same holds for promotion to owner and for owner invitations. List every way to gain the counted thing before designing the check.
- **A new database invariant breaks every test that builds data around it, not only the tests of the feature.** The owned-organization trigger made five e2e specs fail that insert a second owner by SQL, and a session-run test pinned the old event names; my targeted runs of the "related" specs missed them and hosted CI caught them. After adding a trigger or CHECK, grep the tests (all suites, all modes) for raw writes to that table, and run both full Playwright suites before pushing.

## A server page reads only components from a "use client" module (2026-10-08)

The Inventory page imported a label table (`BACKORDER_STATES`) from a client component file. In a server component that
import is a client reference, not the object, so every lookup was `undefined` and the State column rendered empty; no
type check or unit test noticed. Rule: values shared by server and client code (labels, option lists) live in plain
modules; a server file imports only components and types from a client module. `lib/server-client-imports.test.ts`
enforces it.

## A change to the printed invoice needs a new template version (2026-10-08)

Downloads serve the stored PDF of the current template version. A layout change shipped without bumping
`TEMPLATE_VERSION` leaves every PDF downloaded since the last bump looking old, with no error anywhere (it happened once
between two deploys). `tests/test_pdf_render.py` pins the layout code's hash next to the version, so such a change fails
until the version is bumped.

## Units are free text: never print one right after a number (2026-10-08)

The owner found "10 1", "0 of 1 1" and "1 1" in four places one after another: a unit typed as "1" reads as part of the
quantity. Fixing them one by one missed the rest. Rule: a unit gets its own column or is named ("unit: pcs");
`lib/no-unit-after-quantity.test.ts` scans the UI for the adjacent form. When the owner reports one instance of a
display problem, search for every instance before answering.
